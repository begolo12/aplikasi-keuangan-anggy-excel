## Tujuan
Membawa app ke baseline frontend yang layak dijual dan siap dihubungkan ke Neon PostgreSQL nanti, tanpa membuat koneksi database/auth pada tahap ini. Fokus utama: build valid, laporan dapat dipercaya, data demo jujur, backup aman, onboarding jelas, dan UI/responsive/accessibility cukup untuk produksi awal.

## Urutan implementasi

### 1. Pulihkan build dan rapikan struktur JSX
- Perbaiki penutupan JSX yang rusak di `src/App.tsx`:
  - sidebar footer sekitar baris 477-508;
  - row RAB-02 sekitar baris 1050-1100;
  - modal pelunasan sekitar baris 1618-1640;
  - verifikasi kembali parser sampai EOF.
- Jalankan typecheck/build setelah perubahan pertama agar error cascade tidak menutupi masalah lain.

### 2. Buat lapisan perhitungan murni yang dipakai UI dan export
- Tambahkan modul kecil, misalnya `src/finance.ts`, untuk fungsi deterministik:
  - filter transaksi berdasarkan tahun aktif;
  - klasifikasi transaksi internal/pendapatan/pengeluaran;
  - saldo per ledger tanpa menghitung transfer sebagai income/expense konsolidasi;
  - running balance berdasarkan semua transaksi ledger, bukan hasil search/filter;
  - actual bulanan dari transaksi;
  - RAB bulanan dari `months` sebagai sumber utama dan total mingguan/bulanan yang konsisten;
  - RARI dari RAB versus actual;
  - cash flow bulanan dan saldo berjalan;
  - outstanding piutang;
  - depresiasi dan liabilitas aset dengan tanggal laporan eksplisit.
- Gunakan fungsi yang sama di `App.tsx` dan `export.ts` untuk menghapus tabel hard-coded.
- Hapus pembagian `/2` yang tidak dapat ditelusuri, `sisaHutangRumah` hard-coded, dan formula bunga yang mengabaikan tenor.
- Hindari `NOW()` pada laporan; pakai tanggal laporan/tahun yang eksplisit sehingga hasil dapat direproduksi.
- Tetapkan aturan transaksi: transfer memiliki metadata pasangan/correlation ID; income/expense konsolidasi tidak menghitung dua sisi transfer.

### 3. Perkuat model store dan validasi boundary
- Ubah ID baru dari `Math.random()` ke `crypto.randomUUID()` dengan fallback aman bila diperlukan.
- Tambahkan metadata minimal yang tidak menghambat migrasi Neon: `schemaVersion`, `createdAt`/`updatedAt` bila sesuai, dan metadata transfer/reference.
- Tambahkan validasi/normalisasi untuk add/update/import:
  - nominal finite dan tidak negatif;
  - tanggal valid;
  - transaksi memiliki tepat satu arah uang atau aturan eksplisit untuk transfer;
  - tenor/umur positif;
  - array bulan berukuran 12;
  - pelunasan tidak negatif dan tidak melebihi outstanding.
- Perbaiki `catatPelunasan` agar payment terkait parent piutang dan tidak membuat saldo terpisah yang tidak dapat ditelusuri.
- Perbaiki `toggleSchedMonth` agar nilai total konsisten atau total selalu dihitung selector.
- Tambahkan Zustand persist version/migration dan tangani kegagalan localStorage tanpa merusak app.

### 4. Onboarding dan data demo yang jujur
- Tambahkan first-run onboarding ketika tidak ada preferensi setup:
  - `Mulai dari data kosong` sebagai default produk;
  - `Buka data demo` dengan penanda global `Data Demo`;
  - `Impor backup`/`Impor Excel` sebagai jalur nyata yang tersedia.
- Jangan tampilkan nama/angka seed sebagai data pengguna tanpa label.
- Sediakan pengaturan minimal untuk nama pemilik, tahun aktif, saldo awal, dan nama ledger bila model saat ini belum mendukung ledger dinamis penuh.
- Jika ledger dinamis penuh belum aman untuk tahap ini, ubah copy bantuan agar tidak mengklaim pengguna dapat menambah ledger.

### 5. Backup dan import yang dapat dipakai
- Tambahkan export backup JSON berisi `schemaVersion`, `exportedAt`, `appVersion`, dan `data`.
- Tambahkan file picker import backup JSON dengan preview/konfirmasi sebelum replace.
- Validasi file, tampilkan error yang dapat dipahami, dan jangan menghapus data saat import gagal.
- Tampilkan status persistensi: `Tersimpan di perangkat ini` dan peringatan bahwa sinkronisasi cloud belum tersedia.
- Pertahankan export Excel sebagai laporan, bukan sebagai restore source.

### 6. Perbaiki UX, accessibility, dan responsive
- Jadikan semua modal memakai pola reusable dengan:
  - `role="dialog"`, `aria-modal`, labelled title/description;
  - initial focus, return focus, Escape, dan focus trap sederhana;
  - `max-height` + internal scroll pada viewport pendek;
  - backdrop click tidak membuang form tanpa konfirmasi bila form sudah berubah.
- Tambahkan `aria-label` untuk icon-only buttons, `scope="col"`/caption pada tabel penting, dan status live untuk hasil filter/error.
- Implementasikan navigasi keyboard command palette yang saat ini hanya dijanjikan oleh hint `↑↓`, atau hapus hint tersebut.
- Tambahkan `prefers-reduced-motion`.
- Hapus `maximum-scale=1.0` dan `user-scalable=no` dari `index.html`.
- Pastikan toast/modal/tombol mobile memenuhi target 44px.
- Sediakan mode row/card alternatif untuk tabel transaksi/RAB pada mobile bila horizontal scroll terlalu berat.
- Pertahankan palette navy/emerald/amber/rose, tetapi kurangi badge/pill dekoratif dan bedakan radius berdasarkan hierarki.

### 7. Dashboard dan copy produksi
- Ubah headline/summary agar hanya menyatakan hal yang dihitung dari data aktif.
- Hapus klaim `Meningkat dari bulan lalu` jika belum ada pembanding nyata; ganti dengan periode yang eksplisit.
- Filter semua YTD dan laporan menggunakan `s.year`.
- Samakan copy export menjadi 13 sheet di seluruh UI/help.
- Ubah copy `real-time`, `sinkron`, atau klaim lain yang belum benar menjadi deskripsi yang akurat tentang local persistence.
- Hapus em dash dari UI text.

### 8. Metadata deployment dan dokumentasi
- Perbarui `index.html` dengan title/description/theme-color/OG dasar tanpa membuat klaim palsu.
- Tambahkan README produksi: local development, build, Vercel, backup, batasan localStorage, dan rencana Neon.
- Tambahkan `vercel.json` hanya bila diperlukan untuk SPA fallback; karena saat ini tab berbasis state, hindari konfigurasi yang tidak perlu.
- Tambahkan script `typecheck`, `test`, dan smoke validation ringan.

### 9. Tests dan verification
- Tambahkan satu test file kecil berbasis Node/TypeScript yang memverifikasi selector murni dan invariant:
  - saldo ledger;
  - transfer tidak mengubah net consolidated cash;
  - RARI/cash flow berubah ketika transaksi berubah;
  - pelunasan tidak melewati outstanding;
  - depresiasi tidak negatif;
  - filter tahun bekerja;
  - backup round-trip tervalidasi.
- Karena belum ada test runner, pilih solusi minimum yang cocok dengan toolchain yang sudah terpasang; jangan menambah framework besar hanya untuk beberapa fungsi.
- Jalankan `npm run lint`, `npm run build`, dan test/self-check.
- Jalankan server lokal dan lakukan smoke test browser untuk onboarding, tambah transaksi, transfer, filter tahun, backup/import, export, modal Escape, dan viewport mobile.
- Catat hasil verifikasi dan blocker tersisa. Jangan menyatakan siap produksi jika build/test atau alur finansial gagal.

## Batasan yang sengaja ditunda
- Neon PostgreSQL, authentication, workspace/multi-user, billing, dan cloud sync ditunda sampai kontrak frontend/data stabil.
- PWA/offline conflict resolution dan real-time collaboration ditunda karena membutuhkan keputusan backend dan sinkronisasi.
- Ledger dinamis penuh hanya ditambahkan jika tidak merusak kompatibilitas; jika belum, copy produk harus jujur.

## Definition of done tahap ini
- `npm run build` dan `npm run lint` lolos.
- Tidak ada angka laporan hard-coded yang bertentangan dengan store.
- Semua laporan utama memakai selector yang sama.
- Onboarding tidak membingungkan data demo dengan data pengguna.
- Backup/import tervalidasi dan tidak destruktif saat gagal.
- Modal, keyboard, mobile, dan zoom dasar telah diuji.
- README menjelaskan batasan local-only dan langkah integrasi Neon berikutnya.
- Tidak ada klaim produksi yang belum terbukti.
