# Rencana Produksi: Login Page + Neon PostgreSQL Backend

## Arsitektur
- **Frontend**: Vite + React + Tailwind (tetap) dengan rute terproteksi.
- **Backend**: Vercel Serverless Functions (`api/`) dengan koneksi Neon PostgreSQL server-side.
- **Auth**: Email + password, session via httpOnly cookie JWT.
- **Database**: Neon PostgreSQL dengan Drizzle ORM.
- **Data model**: Cloud-first, localStorage sebagai cache offline. Semua tabel punya `workspace_id` untuk isolasi multi-user.

## ⚠️ Keamanan kritis
Connection string Neon **tidak boleh** masuk ke kode client. Ia hanya disimpan di:
- File `.env.local` (untuk dev, di-gitignore)
- Vercel Environment Variables (untuk produksi)
- Hanya dibaca di serverless functions `/api/*`, tidak pernah di `import.meta.env` client.

## Fase 1 — Setup backend & database schema

1. **Install dependencies**:
   - `@neondatabase/serverless` (koneksi Neon dari serverless)
   - `drizzle-orm` + `drizzle-kit` (ORM + migration)
   - `zod` (validasi input server-side)
   - `bcryptjs` (hash password)
   - `jose` (JWT sign/verify)
   - `react-router-dom` (routing + protected routes)

2. **Buat file environment**:
   - `.env.local` berisi `DATABASE_URL=postgresql://...` (hanya dev, gitignored).
   - `.env.example` sebagai template tanpa password.
   - Update `.gitignore` agar `.env*` tidak ter-track.

3. **Buat Drizzle schema** (`lib/schema.ts`):
   - `users`: `id, email (unique), password_hash, created_at`
   - `workspaces`: `id, user_id, name, created_at`
   - `transactions`: `id, workspace_id, tanggal, nsb, pos, uraian, penerimaan numeric, pengeluaran numeric, ledger, transfer_id, receivable_id, created_at, updated_at`
   - `rab_rows`: `id, workspace_id, target ('anggy'|'keluarga'), group, uraian, sat, vol, hs, w1-w4, months jsonb, total, created_at, updated_at`
   - `piutangs`: `id, workspace_id, tgl, nsb, uraian, terbit, lunas, parent_id (nullable), keterangan, created_at`
   - `assets`: `id, workspace_id, jenis, nama, atas_nama, tgl, nilai, dp, bunga, tenor, nilai_pasar, tambah, created_at`
   - `deps`: `id, workspace_id, nama, tgl, nilai, umur, nilai_taksir, kat, created_at`
   - `schedules`: `id, workspace_id, nama, hs, months jsonb, kat, created_at`
   - `settings`: `workspace_id, year, saldo_awal, demo_mode, updated_at`
   - Semua tabel punya index `(workspace_id)` untuk performa.

4. **Jalankan migration** ke Neon via `drizzle-kit push`.

## Fase 2 — API serverless functions (`api/`)

5. **`lib/db.ts`**: singleton Neon client + Drizzle instance (server-side only).
6. **`lib/auth.ts`**: JWT sign/verify, hash/compare password, session cookie helper.

7. **Auth endpoints**:
   - `POST /api/auth/register` — email+password → create user + workspace → set cookie.
   - `POST /api/auth/login` — verify credentials → set cookie.
   - `POST /api/auth/logout` — clear cookie.
   - `GET /api/auth/me` — verify cookie → return user/workspace.

8. **Data endpoints** (semua butuh auth cookie):
   - `GET /api/state` — load semua data workspace (transactions, rab, piutangs, assets, deps, schedules, settings).
   - `PUT /api/state` — bulk replace (untuk import/sync).
   - `POST /api/txs`, `PATCH /api/txs/:id`, `DELETE /api/txs/:id`
   - `POST /api/rab`, `PATCH /api/rab/:id`, `DELETE /api/rab/:id`
   - `POST /api/piutangs`, `DELETE /api/piutangs/:id`
   - `POST /api/assets`, `DELETE /api/assets/:id`
   - `POST /api/deps`, `DELETE /api/deps/:id`
   - `POST /api/schedules`, `DELETE /api/schedules/:id`
   - `PATCH /api/settings` — year, saldoAwal, demoMode

9. **Validasi server-side** dengan zod: nominal tidak negatif, tanggal valid, field required, transfer validasi saldo.

## Fase 3 — Login page & routing

10. **`src/pages/Login.tsx`**: form email+password, link register, redirect ke dashboard setelah sukses.
11. **`src/pages/Register.tsx`**: form signup email+password+confirm.
12. **`src/lib/auth-client.ts`**: helper client-side untuk cek session (`GET /api/auth/me`), redirect kalau belum login.
13. **Routing**: `react-router-dom` dengan `ProtectedRoute` wrapper. Kalau belum login → redirect ke `/login`.
14. **`src/main.tsx`**: tambah `BrowserRouter` + `AuthProvider` wrapper.

## Fase 4 — Integrasi store ke API

15. **Refactor `store.ts`**:
    - Tambah `workspaceId`, `authToken`, `syncStatus` ke state.
    - Ubah actions agar memanggil API (optimistic update + background sync).
    - `loadFromServer()` saat login sukses: fetch semua data dari `/api/state`.
    - `syncToServer()` setelah setiap mutasi: POST/PATCH/DELETE ke endpoint.
    - Zustand `persist` tetap ke localStorage sebagai cache offline + recovery.
    - Jika offline → simpan ke queue, sync saat online lagi.

16. **`App.tsx`**:
    - Hapus onboarding yang lama (ganti: kalau belum login → login page).
    - Tambah loading state saat sinkronisasi awal.
    - Tambah tombol "Logout" di sidebar/footer.
    - Tambah indikator status sinkronisasi (Tersimpan di cloud / Sinkronisasi... / Offline).

## Fase 5 — Vercel config & deploy

17. **`vercel.json`**: SPA fallback untuk client routes + API functions.
18. **Vercel env vars**: set `DATABASE_URL` di dashboard Vercel (Environment Variables, production + preview).
19. **Build command** tetap `npm run build`; output tetap `dist`.
20. **API directory**: Vercel auto-detect `api/**/*.ts` sebagai serverless functions.

## Fase 6 — Testing & verifikasi

21. **Test alur lengkap**:
    - Register → login → tambah transaksi → cek data tersimpan di Neon.
    - Logout → login ulang → data masih ada.
    - Tambah RAB, aset, piutang, pelunasan → semua tersinkron.
    - Export Excel tetap jalan (client-side, dari data store).
    - Backup/import JSON tetap jalan.
    - Mobile 390px: login page responsive, tidak overflow.
22. **Validasi**: `npm run typecheck && npm test && npm run lint && npm run build`.
23. **Security check**: `DATABASE_URL` tidak muncul di client bundle (grep `dist/`).

## Fase 7 — Polishing produksi

24. **Error states**: API error → toast, retry, tidak crash app.
25. **Rate limiting hint** di register/login (basic).
26. **Session expiry handling**: kalau cookie expired → redirect ke login dengan pesan.
27. **Privacy notice** singkat di login page.
28. **README update**: dokumentasi setup, env vars, deploy, security.
